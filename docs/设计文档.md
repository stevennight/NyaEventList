# NyaEventList 设计文档

## 0. 文档说明

本文档是产品/功能层面的设计文档，描述“为什么做”“做成什么样”“给谁用、怎么用”。
技术实现细节（技术选型、数据库表结构、模块划分、接口设计）见 [开发文档](./开发文档.md)。

设计依据：对你现有的 `202501-工作统计表.xlsx` 做了完整结构分析（共 14 个 Sheet），经你确认后，本期只处理其中 5 个：「需求列表」「非需求任务列表」「明细」「月日常性工作项」「选项」；其余（待办、人天分值表、需求绩点明细、月绩效系列、日汇总、Sheet3）不在本系统范围内，不做导入也不做功能设计——「待办」虽然不导入，但它启发了下面 5.1 的“进度看板”这个全新能力，只是不从旧表迁移数据，直接在新系统里用。本设计尽量复用你已经跑通的字段和统计逻辑，只是把“Excel 手工维护”变成“应用自动维护”。

## 1. 背景与痛点

你目前用一份多 Sheet 的 Excel 记录工作，核心痛点：

1. **记录链路割裂**：任务/需求定义在「需求列表」「非需求任务列表」，实际工时记录要跳去「明细」，再手动核对编号是否对得上，来回切换工作簿/Sheet。
2. **任务不直观**：几百条任务是一张扁平表格（399 行需求 + 1997 行非需求任务），要找到某个任务靠肉眼扫描或 Ctrl+F，缺少按状态/时间/系统聚合的视图。
3. **重复录入**：任务标题、内容在「需求列表」「明细」里近似重复抄写，改一处经常忘改另一处。
4. **系统分类越来越难辨认**：「选项」Sheet 里的“系统”下拉已经堆到近 50 项，命名上大量靠字符串前缀区分父子关系（如“HRM”“HRM-人事管理”“HRM-招聘管理”“HRM/OA权限系统”），本质是一个隐藏的树状结构硬塞进一个扁平列表，新增/查找越来越费劲。
5. **非结构化的分类信息**：一些重要标记只是硬编码在标题/内容文本里，不能筛选、不能统计。

## 2. 项目目标

做一个本地桌面应用，把“任务定义”和“时间记录”合并到同一个交互界面里：看着日历/时间轴录入工时，左右两侧就是任务面板，不用切换工作簿；任务分类、需求方来源等做成可扩展的字典 + 标签，而不是写死的下拉；并在此基础上补齐搜索、统计、导入、导出能力。

非目标（本期不做）：
- 多人协作/云端实时同步（单机单用户工具，[开发文档](./开发文档.md) 里数据存储部分会说明后续如何平滑扩展到同步）
- 严格的项目管理功能（甘特图依赖关系、资源排期算法等）——只做“记录 + 查看 + 统计”，不做“计划推导”

## 3. 术语定义

| 术语 | 说明 | 对应旧表 |
|---|---|---|
| 任务 (Task) | 一个需求或非需求事项，是记录时间的“挂靠对象” | 「需求列表」+「非需求任务列表」合并概念 |
| 时间记录 (Time Entry) | 某天某时段/某时长，针对某个任务做了什么 | 「明细」 |
| 需求方 (Requester) | 任务的提出方/对接人 | 「需求列表」的“产品”列 |
| 字典 (Option List) | 可编辑的下拉选项集合，如系统、状态、工作内容划分 | 「选项」Sheet |
| 标签 (Tag) | 自由多选、无固定含义的标记 | 旧表里散落在文本中的「【重点】」等 |
| 待安排 (Backlog) | 计算状态：任务还没有被排进日程（没有任何时间记录），任何任务只要还没排期都会落入这个状态 | 无对应，纯计算状态，不从旧表导入 |
| 进度看板 (Progress Board) | 按状态分列展示所有“未完成”任务，用于跟进项目进度、盯截止日期 | 无对应，新增能力（灵感来自你原来手工维护「待办」的习惯，但不迁移「待办」数据） |
| 流水录入 (Log) | 键盘优先的明细表，一行一条时间记录，日常记录的主入口 | 「明细」Sheet 的录入方式 |
| 视图 (View) | 日程的展示方式：流水录入 / 纵向日历 / 横向时间轴 / 进度看板 | 无对应，新增能力 |

## 4. 核心使用流程

### 4.1 日常记录工时（最高频操作）
打开应用 → 默认落在“流水录入”表的最后一行 → 任务格里打字搜任务（或 Ctrl+D 带出上一行的任务）→ 写具体内容 → Ctrl+Shift+; 填结束时间 → Ctrl+Enter 保存，下一行的开始时间已经接好了。全程不碰鼠标、不弹窗，详见 5.6。想看全貌或拖着微调，再切到纵向日历。

### 4.2 新建任务并让 AI 建议标题
在任务面板点“新建” → 先写清楚内容/背景 → 点「AI 推荐标题」→ 应用调用配置好的 AI 接口返回 2-3 个候选标题 → 选一个或手动改 → 选系统/类型/需求方等字典字段 → 保存。
也可以反向触发：正在记一条时间条目、还没建任务时，输入了内容后同样可以呼出“用这段内容生成任务标题”。

### 4.3 查找任务
任务面板顶部搜索框，支持模糊搜索（默认）；设置里可以切到本地向量搜索或云端向量搜索（见 5.7），得到更“语义相近”的结果，比如搜“兼岗权限”能带出「HRM/OA权限系统」相关任务。

### 4.4 安排未排期任务
面板切到“待安排”Tab → 看到还没排期的任务 → 直接拖到日程视图的某一天 → 系统据此建立第一条时间记录，任务自动从“待安排”移出。

### 4.5 跟进未完成事项（进度看板）
切到“进度看板”视图 → 按状态分列看所有还没完成的任务（不管排没排期、记没记时间）→ 每张卡片带着期望完成时间，临近/超期的会高亮 → 可以直接把卡片拖到别的状态列，或点开补记录。不用再手动维护一张单独的表格来盯进度了。

### 4.6 查看统计
统计面板选时间范围 → 看工时分布（按系统/按类型/按需求方）、任务吞吐、日均工时曲线。

### 4.7 导出/复制
在日程视图里框选若干时间块，或者在统计面板选中某天/某个时间范围 → 右键/工具栏“复制”或“导出” → 选 Excel 或 JSON 格式 → 落盘或复制到剪贴板。

### 4.8 导入旧数据
首次启动（或设置里随时触发）→ 选择旧的 `.xlsx` 文件 → 应用自动识别「需求列表」「非需求任务列表」「明细」「月日常性工作项」「选项」这 5 个 Sheet → 给出字段映射预览（可调整）→ 确认导入。旧编号（A01/B03…）原样保留，作为“旧系统编号”字段，方便你对照历史记录。其余 Sheet（待办、人天分值表、需求绩点明细、月绩效系列、日汇总、Sheet3）不参与导入。

## 5. 功能设计

### 5.1 视图：流水录入 / 纵向日历 / 横向时间轴 / 进度看板

- **流水录入**：默认打开的视图，是日常“记一笔”的主入口——一张按 Excel「明细」列顺序排的表格，一行一条时间记录，全键盘操作，详见 5.6。纵向日历退到“看全貌、拖拽微调”的位置，不再要求你靠鼠标拖着录入。

- **纵向日历**：类似日历应用的周/日视图，一列代表一天，纵轴覆盖完整一天 **00:00–24:00**（不是只显示白天那一截），默认打开时自动滚动到常用工作时段（比如 07:00）附近，不用一打开就对着一堆空白的深夜时段，但往上滚就能看到凌晨、往下滚能看到深夜——早起或加班到很晚的记录都有地方放，不会出现"时间轴到某个点就没了"的情况。时间块按实际起止时间摆放到分钟。这是唯一一个精确到分钟、可以直接编辑时间记录的视图，最贴近你现在按“开始时间-结束时间”记录的习惯，具体的拖拽/编辑交互见 5.6。
  - **重叠的处理**：同一时段有两条记录是正常情况（比如一边开会一边被临时插了个别的事），**并排缩窄显示，不是叠在一起**——两条记录各占那一列宽度的一半，都能看全标题、都能单独点开编辑；如果同时段挤了 3 条以上，每条会窄到看不清标题，这种情况下改成一个更明显的"多条重叠"提示块，点开先弹一个小列表选是要看哪一条，而不是继续无限缩窄挤在一起。
- **横向时间轴**：一行代表一个任务，横轴是日期，格子里显示当天在这个任务上花的时长（数字或色块深浅）。**这不是甘特图**（甘特图画的是任务起止跨度的长条；这里画的是“某任务每一天分别花了几小时”的热力图），刻意做成按天聚合，不追求分钟精度——它回答的是“这个任务这段时间投入趋势怎么样”这种概览问题，不是用来编辑记录的。想看/改某天的具体记录，点格子会弹出那天这个任务的记录列表，点进去用的是跟纵向日历同一个编辑弹窗（见 5.6）。如果你只需要“记录 + 编辑”，纵向日历一个视图基本够用；横向时间轴是给“回顾某个拖了很久的任务这段时间投入节奏”这种场景加的，价值没有另外两个视图那么刚需，开发文档的阶段规划里也把它排在纵向日历之后、单独一个阶段，如果用起来发现确实用不上，可以先砍掉。
- **进度看板**：跟前两个视图不同，这个不是按时间排布，而是按**状态**分列（列的顺序/名称跟着“状态”字典走，比如 待处理/开发中/搁置中…），每列里是该状态下所有任务卡片。这个视图专门回答“现在有哪些事还没完成”：
  - 默认只显示“未完成”性质的状态列，终态列默认折叠，可以手动展开查看。判断某个状态算不算“完成”，靠状态字典里每个选项自带的 **是否为完成态** 开关（字典管理页可调）：默认只有**已上线、已终止**算完成态，**已交付不算**——交付出去了不代表事情彻底结束（可能还要跟进反馈、修复问题），这个默认值直接采用，不再是开放问题。
  - 卡片显示标题、需求方、系统、**期望完成时间**。临近截止会标黄、超期会标红，“临近”的天数阈值可在设置里调整，默认 **3 天**；没有填期望完成时间的任务不参与这个判断，正常显示、不特殊标记。
  - 可直接拖拽卡片换列来改状态，不用进编辑弹窗。
  - **数量控制**：看板默认展示的是"全部未完成任务"，如果任务基数大（旧表光是非需求任务列表就快 2000 行），未完成的堆起来也可能有大几十上百张卡片，光靠折叠终态列不够。看板顶部复用任务面板同一套**搜索/筛选**（5.2）——默认展示全部，但你可以直接在看板里按系统/需求方/标签筛一下，只看当前真正关心的那部分；这样"看板要不要限流"这个问题不用系统替你做主，你筛到多细看板就有多干净。
- 顶部切换四种视图，选择会记忆（存在本地设置里）。
- 四种视图共享同一份任务/时间记录数据，只是展示维度不同（流水录入按“行”，纵向按“天”切片，横向按“任务”切片，看板按“状态”切片）。

### 5.2 任务面板（左/右可停靠）

- 停靠位置可在设置里选左或右。
- 顶部：搜索框（带当前搜索模式的小图标/角标）+ **筛选器**入口。**搜索永远搜全部任务**，不受当前 Tab 限制——不管你停在“未完成”还是“已完成”Tab，只要输入关键词就是在全库里找，保证任何时候都能搜到任何任务（哪怕是很久前已终止的旧需求）。搜索结果排序分两段：**进行中/待安排的任务排在前面，其余（已完成/已终止）排在后面**，段内再按相关度/引用量排序——这样大部分时候你要找的当下还在处理的事优先冒出来，但历史任务依然搜得到，不会因为“默认只看未完成”而漏掉。这个分段逻辑复用 Tab 里“未完成”的判定口径（状态字典的“是否为完成态”开关，见 5.1 进度看板），不用另外维护一套规则。
- **筛选器**不是只能靠打字：点筛选器图标弹出一个小面板，按字段选值（系统/需求方/状态/标签，可以叠加多个条件），确认后跟搜索框一样过滤面板列表——这样"我要看某个系统底下所有任务"这种需求，不用先去字典管理页绕一圈再跳回来。5.4 里"字典管理页点『筛选相关任务』跳过来"，走的正是这同一套筛选器，只是从另一个入口触发、自动帮你把条件填好；两个入口共享同一份筛选逻辑，不是两套。
- **常用任务区**：面板最上方固定展示一组手动置顶的任务（比如“日常会议”“工作统计”这类长期高频事项），不受下面的筛选/排序影响，随时点得到。对应旧「月日常性工作项」Sheet——那张表本质就是你自己手工维护的一份“这个月常挂的例行任务”速查清单（且里面已经有 `#N/A` 说明公式其实也维护得比较吃力了），迁移过来变成一个可以随手点“置顶/取消置顶”的开关，不用再手动整理清单。
- Tab：**未完成**（默认）、**待安排**、**已完成**、**全部**，可另存自定义筛选（比如“系统=CRM-会员端 且 状态=开发中”）。“待安排”是时间维度（有没有排进日程），跟 5.1 的“进度看板”（状态维度，做到哪一步）是两件事：一个任务可能已经排了日程但状态还没推进，也可能状态在推进但还没被具体安排到某一天——两个视角都需要，互相不替代。
- 默认排序：未完成 + 最近有记录 + **引用量倒序**（“引用量”= 关联时间记录条数，对应你说的“按引用量倒序”，也就是被记录得越频繁的任务排越前）。排序方式可切换为：最近更新、创建时间、预计人天、需求方、系统。
- 卡片信息：标题、**需求/非需求类型标记**（对应旧表 A/B 编号那种一眼能看出类别的直觉，用小色块或字母角标，不是要点开才知道）、系统 chip、需求方、状态 chip、累计工时、最近一次记录时间、标签。
- 卡片可直接拖拽到日程视图对应的时间格里，快速生成一条时间记录；**点击卡片本体（非拖拽）打开任务编辑弹窗**，改的是任务自己的字段——标题、类型、系统、例行工作内容划分、状态、需求方、预计人天、开始/期望完成时间、标签，这些是任务级别的信息。这跟点日历色块打开的时间记录编辑弹窗（见 5.6）是两层不同的东西：一个改“这个任务是什么”，一个改“某天在这个任务上具体做了什么、花了多久”，两层弹窗字段不重叠、不要合并成一个。

### 5.3 任务字段设计（去重后）

沿用旧表字段，但做了合并去重：旧表里「需求列表」的“简要内容”和「明细」的“工作内容”本质都是对同一件事的描述，容易一份改了另一份没改，所以设计里**任务只保留“标题”一个概括性字段，具体内容只出现在时间记录里，不在任务层面重复摘要**。

| 字段 | 说明 | 旧表来源 |
|---|---|---|
| 标题 | 简短概括，可 AI 生成建议 | 需求列表.标题 / 非需求任务列表.标题 |
| 类型 | 需求 / 非需求（例行事务） | 两张表本身的区分 |
| 系统 | 字典字段 | 需求列表.系统 |
| 版本号 / 分支 | 保留，非必填 | 需求列表.版本号/分支 |
| 例行工作内容划分 | 字典字段（执行类/辅助类…） | 两表同名列 |
| 状态 | 字典字段，每个选项自带“是否为完成态”开关（见 5.1 进度看板） | 需求列表.状态 / 非需求任务列表.状态 |
| 需求方 | 关联「需求方」实体，**一个任务可以有多个需求方**，见 5.5 | 需求列表.产品（原表里“张三/李四”这种斜杠分隔的就是多个） |
| 所属月份 | 保留，用于归档统计 | 需求列表.所属月份 |
| 预计人天 | 数字 | 需求列表.预计人天 |
| 开始时间 / 期望完成时间 | 前者排期参考，后者是截止日期，进度看板里临近/超期会高亮；两个字段任何时候都可以手动填或改，不限于导入 | 需求列表.开始时间/结束时间，非需求任务列表同名字段 |
| 需求池编号 / 旧系统编号 | 追溯字段，导入时自动填，只读 | 需求列表.需求池编号 / 编号 |
| 标签 | 自由多选 | 无（新增，见 5.5） |
| 引用量（计算字段） | 关联时间记录数，用于默认排序 | 无（新增） |

「需求对接用时/功能架构设计用时/…/合计用时」这类旧表里按工作阶段拆分的用时列，**不再作为任务的固定字段**，而是由每条时间记录的“工作内容划分”（对应旧「例行工作工作内容」字典：需求对接/功能架构设计/功能开发/功能自测/功能联调/功能上线…）在统计时自动汇总得出，避免任务表和明细表两处对不上账。

### 5.4 字典治理：筛选 + 批量修改（解决“系统越来越多、分不清”）

现状问题：「选项」Sheet 里“系统”一列已经堆了近 50 个值，其中不少是同一个系统的不同叫法——比如「选项」下拉里登记的是 `JAVA-招聘系统`，但「需求列表」里任务实际用的却是 `招聘系统（JAVA）`，两个字符串完全对不上，类似的还有 `餐补系统（JAVA）`/`FRS财报系统（JAVA）`/`ADS（JAVA）` 这批“系统名（JAVA）”写法。这类命名本身就不规整，**不适合靠程序自动猜层级关系去拆分**——猜错了反而会制造新的重复项。所以设计方案不做自动分层，改成给你一套直接、可控的整理工具：

1. **系统字典保持扁平**，不引入大类/子项的树状结构；靠**输入即搜**的下拉选择器（打字过滤）解决“50 项不好选”的问题，不需要先点开一层分类。
2. **筛选 + 多选 + 批量修改**（核心工具，不止用于系统字段）：
   - 任务面板支持一个“选择模式”开关，打开后每张任务卡片前面出现勾选框，可以从当前筛选结果里挑几张勾选，也可以直接“全选筛选出来的全部”——两种都要支持，挑几个还是全要看你当时想改的范围。
   - 勾选至少一项后，面板底部弹出批量操作栏：选“要改哪个字段”，再选“改成什么”（复用第 5 点的“选择或新建”控件），确认后一次性写入所有选中的任务。
   - **只有真正“对这批任务来说应该是同一个值”的字段才能批量改**：系统、状态、例行工作内容划分、需求方，这几个字段允许批量改（需求方是多值字段，批量改时要选模式：“追加为需求方”保留原有的、“替换全部需求方”、以及从字典管理页跳过来时多一个“把『某某』换成……”——只换掉这一个，任务上的其他需求方不动，这正是合并两个重复需求方要用的）；标题、具体内容、预计人天、开始/期望完成时间这些每条任务天生不一样的字段，不出现在批量修改的可选字段里——批量改的前提是“这批任务本来就该统一成同一个值”，不是“把这批任务变得一模一样”。
   - 整理系统字典重复项的实际操作就是：筛出用旧写法（比如“招聘系统（JAVA）”）的任务 → 全选 → 批量把“系统”改成你想保留的写法（比如“JAVA-招聘系统”）→ 旧选项没有任务引用了，去字典管理页删除。
3. **字典管理是独立界面，不塞在设置里**：左侧导航单独给一个入口（跟“日程”“统计”“设置”平级），不是设置页里的一小块。原因很直接——系统字典能长到近 50 项，塞进设置里的一小块列表根本没法看，值得单独给一屏空间。页面里按字典类型分 Tab（系统 / 状态 / 例行工作内容划分 / 需求方类型 / 需求方，需求方见 5.5），每个 Tab 顶部有**搜索框**，输入即按名称过滤当前列表；筛选相关的次要选项（比如“只看未引用”）收进页面顶部一个“⋯”菜单里，不常驻占地方——**不做“疑似重复”的自动识别**，是不是重复、要不要合并，交给你自己判断，系统不替你猜。
   - 每一行只常驻显示名字、引用计数这些看一眼就有用的信息；**具体能对这一项做什么操作，收进这一行自己的“⋯”菜单里**，不是每行都摆一个常驻的文字按钮——不然系统字典铺开小 50 行、每行都挂一个按钮，页面照样乱。行内菜单里：引用数大于 0 时是“筛选相关任务并批量修改”，点一下直接跳到日程界面，任务面板自动套用筛选器（就是 5.2 那个筛选器，不是新开一套）选出所有用这个选项的任务、自动进入选择模式并全选，批量操作栏也已经把目标字段选好，你只要选新值、确认；引用数为 0 时是“删除”。
4. 这套“筛选 + 批量修改 + 清理无引用项”不是系统字段专属，需求方、状态、例行工作内容划分等任何字段需要整理重复/过时值时，都是同一套操作；需求方类型这种量很小（就 4 个左右）、直接挂在“需求方”实体上的字典，整理成本低，字典管理页里编辑单个需求方的类型就够了，不需要走批量流程。
5. **表单里的“选择或新建”**：任何字典/实体字段（系统、状态、例行工作内容划分、需求方类型、需求方、标签）在任务新建/编辑表单里，都用同一种**可搜索、可直接新建**的下拉控件——输入内容实时过滤已有选项，没有完全匹配的就在列表最下面出现一条“新建『刚才输入的内容』”，点一下就创建并选中，不用先跳到字典管理页面建好选项再回来选。新建的选项立刻计入字典管理页面，两边是同一份数据；批量修改栏里“改成什么”用的也是这同一个控件。

这个方案跟“自动分层拆分”比起来责任更清楚：由你决定哪些名字算同一个系统、统一成哪个写法，系统只负责把批量修改这件事做得快，不替你做可能出错的语义判断。

### 5.5 需求方与分类体系（重点设计）

针对你提的问题——需求方要不要分“业务”还是“自己部门的人”，以及是否要更灵活的标签——设计成两层：

**第一层：需求方类型（可编辑字典，不是写死的枚举）**
- 命名为「**需求方类型**」，默认预置：`业务方` / `内部协作` / `外部机构` / `其他`。
- 和旧表「选项」Sheet 里“系统/例行工作内容划分/例行工作工作内容/任务状态”是同一套机制的延伸——所有这类“有限选项、但会随时间增删”的字段，都走统一的**字典（Option List）**模型，用户可以在字典管理页面自由增删改选项、调整排序，不需要改代码。
- 这样命名的原因：“业务”和“内部同事”本质是在回答“这个需求方跟我是不是同一个团队/汇报线”，用「内部协作」而不是「自己人」这种口语化措辞，是为了未来即便团队结构变化（比如外包、跨部门借调）也还能归类，不用改字段含义。

**需求方本身也是可复用、可搜索、可随手新建的实体，不是自由文本框；一个任务可以挂多个需求方**（旧表“产品”列里用斜杠写的多个人，导入时拆成多个；表单里逐个搜索添加，显示成一排小标签，各自带类型）
- “需求方”跟“系统”会遇到同一类问题：同一个人/同一个业务方，这次录入打“产品-甲”，下次可能打“陈xx”“产品部陈某”，字符串对不上就没法按需求方聚合统计。所以需求方走 5.4 第 5 点说的**“选择或新建”**控件：任务表单里输入名字，实时匹配已经录入过的需求方，没有就直接新建一个（默认类型先给「其他」，之后在字典管理页面里再补充/修正类型），不会两次录入变成两个不同的人。
- 这个模式不是需求方专属——以后如果要加“负责人”“协作人”这类人员字段，同样指向这一份可复用的人员列表，走同一套控件，不需要每加一个人员类字段就重新设计一遍。

**第二层：标签（完全自由，多对多）**
- 不预设枚举，用户随手打字创建，比如「重点」「后续补充」「临时插入」「待产品资料」——这类标记本质上就是你平时会在标题/内容里手写的方括号备注。现在把它们变成结构化标签，就能直接筛选/统计“这个月有多少个【重点】任务”，而不是人肉翻文本。
- 标签可以挂在“任务”上，也可以挂在“需求方”上（比如给某个需求方打上「高优先级客户」），复用同一套标签系统。

两层搭配的意义：字典解决“少量、稳定、需要统计聚合”的分类（比如按需求方类型做工时分布图）；标签解决“多样、易变、临时性”的标记，不需要每加一种新情况就去改字典结构。

### 5.6 时间记录（流水录入 + 纵向日历）

**流水录入（主入口）**：你在 Excel 里 Ctrl+D、Ctrl+;、Ctrl+Shift+; 那套手感，是这个视图要对标的——全程不碰鼠标、不弹窗。列顺序照搬旧「明细」表：**任务 → 工作内容划分 → 具体内容 → 日期 → 开始 → 结束 → 用时**，表格最底下永远留一行空白的“新行”，就在那一行里填。

- **任务直接搜**：任务格里打字，标题、旧编号（A201）、系统、需求方、需求/非需求都能搜到，回车（或 Tab）选中第一条，不用再去任务列表里翻半天、复制编号回来粘。
- **Tab** 换格，**↑/↓** 在上下行的同一格之间移动，**Enter** 换到下一格（在“结束”格按 Enter 就是保存）。
- **Ctrl+D**：复制上一行**同一格**的内容（跟 Excel 一样是逐格的：在“任务”格按就带出上一行的任务，在“划分”格按就带出上一行的划分，时间格同理）。
- **Ctrl+;**：这一行的日期填今天。**Ctrl+Shift+;**：把当前时间（精确到分）填进当前的时间格，不在时间格里就填“结束”。
- **Ctrl+Enter**：保存这一行，并立刻开下一行——**新行的日期沿用、开始时间自动等于上一条的结束时间**、划分沿用上一条，光标直接落在“任务”格。连续记录就是“搜任务/Ctrl+D → 写内容 → Ctrl+Shift+; → Ctrl+Enter”。
- 时间可以直接敲数字：`930`、`9:30`、`1805` 都认；日期 `9-16`、`0916` 也行。结束不晚于开始会当场标红并说明（跨天工作拆成两条，见下文），不会静默保存。
- **复制粘贴整行**：点行号选中一行（Shift/Ctrl 点可多选），Ctrl+C 复制，是制表符分隔的文本，既能粘回本表、也能粘到 Excel。粘贴的规则：①光标在新行时粘一行，只带入任务、划分、内容，日期和开始时间仍按“接着上一条”自动算，补个结束时间就行；②粘多行则直接各生成一条记录，记得核对日期时间；③**从 Excel「明细」表复制的行也认**（第一列是 A/B 开头的编号，按编号匹配任务），匹配不到任务的行会跳过并告诉你是哪几行，不会悄悄丢。
- 已有的行可以直接改任何一格，改完立即生效；行末“×”删除。表格默认显示当前所在这一周（顶部的日期范围切换），底部汇总本周条数和总工时。

**纵向日历**用来看全貌和拖拽微调，下面是它的编辑手势。

每条记录字段：所属任务、日期、开始/结束时间（或者“不按时间计算，只填时长”开关，对应旧表「是否按时间计算」列——你旧表里很多条目开始/结束时间都是 00:00:00，其实是用总时长而非精确打卡时间）、工作内容划分（字典）、具体内容（文本，这里才是详细描述，不是标题复制，对应你旧「明细」表里“需求对接：评审会；相关功能沟通”这种颗粒度）。一个任务当天可以有多条时间记录（对应旧「明细」里同一编号多行）。

纵向日历里也能直接改时间记录（横向时间轴是概览，不可编辑，见 5.1），三种手势：

1. **新建**：从任务面板把任务卡拖到日历空白处松手，按落点算出开始时间，默认给 1 小时时长，松手即创建、可以接着调整。
2. **拉伸改时长**：鼠标移到已有色块的上边缘或下边缘，指针变成可调整的样式，按住往上/下拖——拖的时候实时显示当前的时间点，每 5 分钟一档，松手保存。这个操作只动开始或结束其中一边，另一边不变。
3. **整体挪动**：按住色块中间拖动，可以挪到同一天的别的时间段，也可以直接拖到别的日期列——这跟“新建”共用同一套判断逻辑，区别只是这次挪的是已有记录而不是新建一条。

**点击色块弹出编辑框**，颗粒度对齐你原来在 Excel「明细」表里维护的那些字段：所属任务、日期、开始/结束时间（或“不按时间计算”开关+总时长）、工作内容划分、具体内容，改完保存；这里也能直接删除这条记录，或者把它转给别的任务（改“所属任务”）。拖拽（手势 2/3）和点击弹编辑框（手势 4）改的是同一份数据、同一份校验，只是入口不同——拖拽图快，弹窗改得细，两者都可以把时间精确到分钟，不会因为走了拖拽就丢精度。色块上固定有一个小编辑图标，点它必定打开编辑框，不需要先判断“这是点击还是拖拽”，避免手抖几像素就被误判成拖拽、编辑框弹不出来。

横向时间轴的格子不能直接改，但点一下会弹出“这天这个任务的记录列表”（可能不止一条），列表里点进某一条，打开的还是这同一个编辑框——所有视图共用一套时间记录的读写和编辑界面，不是各画一套。

**跨天的处理**：一条时间记录不能跨越午夜——日期还是以“天”为最小单位，跟旧「明细」表一致（旧表的开始/结束时间本来就是相对当天的，没有跨天概念）。两条编辑路径都要给出一致的提示，不能一条挡一条不挡：
- 在编辑框里手动打字，如果结束时间填得比开始时间早（说明是想表达“从今晚做到次日凌晨”这种情况），编辑框会提示“结束时间早于开始时间，跨天的工作建议拆成两条记录：今天 23:xx–24:00，明天 00:00–xx:xx”，不会帮你静默处理成一个奇怪的时长，也不强行不让你保存——你确认要拆就手动建第二条，逻辑很直接。
- 在纵向日历里拖动色块底边往下拉，拖到当天 24:00 会拉不动，同时浮动提示条从正常的“时间·时长”变成“已到 24:00 · 跨天请拆成两条记录，次日从 00:00 开始”，而不是像什么都没发生一样悄悄停在 24:00——拖拽和打字两条路都要让你看得懂“为什么到这就停了、接下来该怎么做”。次日 00:00 开始的那一段直接在次日的日期列里新建一条就行，日历本身覆盖到 00:00-24:00 整天，不存在“次日凌晨没地方放”的问题。

**更贴近实际记录习惯的两个快捷方式**：
- **“现在”按钮**：编辑框的开始/结束时间输入框旁边各有一个“现在”按钮，一键填入当前时间（精确到分钟），对应你现在用快捷键插入当前时间的习惯，不用自己看表再手动敲。
- **“接着记”**：日程视图给一个“接着记”入口（工具栏按钮，或者某一天列的空白处右键也行）——点开是个轻量的新建框，**开始时间自动等于你当天最后一条记录的结束时间**，你只需要选任务、写具体内容，不用管时间；这是你原表里最常见的记录模式（一件事接一件事，很少中间空档），比每次都重新定位开始时间快得多。跟别的记录时段重叠的场景（比如临时插了个事）还是走前面的拖拽/点空白新建，两种方式并存，看当下是不是“紧接着上一条”。

### 5.7 搜索能力（可切换的三种模式）

采用“可插拔搜索 Provider”设计，三种模式共存、可随时切换：

1. **关键词模糊搜索**（默认）：基于 SQLite 全文索引 + 子串匹配，覆盖标题、内容、标签。零依赖、零成本、响应快。
2. **本地向量搜索**：使用本地 embedding 模型做语义相似匹配。模型**不随应用内置**，用到时在设置里按需下载（几十到几百 MB），不用时可以删除释放空间；离线可用，无 API 调用成本。
3. **云端向量搜索**：调用你配置的 AI 服务商的 Embedding 接口，效果通常最好，但依赖网络、有调用成本。

切换搜索模式时，应用会在后台对已有任务做一次性重建索引（因为不同模型/供应商产出的向量不可比，必须重新计算）。由于你的数据量很小（旧表全部任务加起来才几千条），本地重建几秒内完成，云端批量调用也就几十秒。重建期间搜索自动退回关键词模式兜底，不会出现“搜不到”的空窗期。新建任务之后自动增量索引，不需要手动触发。

无论用哪种模式，索引对象都是**全部任务**（不管完成没完成），保证 5.2 里说的“搜索能覆盖全库”；三种 Provider 只负责算相关度，未完成优先展示的排序规则在结果返回后统一处理，跟用哪种搜索模式无关。

### 5.8 AI 任务标题推荐

- 设置里配置 AI 服务商（支持任意 **OpenAI 兼容接口**，包括官方 OpenAI 以及国内各类兼容 Chat Completions / Responses 格式的服务），填 Base URL、API Key、模型名、接口格式。
- 任务编辑/新建弹窗里，输入内容后点「AI 推荐标题」，返回若干候选，点选或者手动修改后保存。
- 同一套服务商配置也可以复用给「云端向量搜索」的 Embedding 调用（见 5.7），设置里分别为“标题生成”“向量搜索”指定用哪个已配置的服务商，避免重复填 Key。

### 5.9 统计模块

- 时间范围筛选：本周/本月/自定义区间。
- 维度：按系统、按需求方类型、按标签、按状态的工时分布；任务完成数/吞吐趋势；日均工时曲线。
- 统计结果同样支持导出（见 5.10）。

### 5.10 导出与复制

- 选取范围：日程视图里框选的时间块 / 指定单天或多天 / 统计面板当前筛选结果。
- 导出格式：**Excel**（贴近你旧表列名习惯，方便你按老流程继续用）、**JSON**（结构化，方便脚本/自动化消费）。
- 支持“复制到剪贴板”（小范围数据，如选中几条记录）和“导出为文件”（大范围数据）两种触发方式。

### 5.11 数据导入（旧 Excel）

- 只识别并导入以下 5 个 Sheet，其余一律忽略：
  - 「需求列表」「非需求任务列表」→ 任务
  - 「明细」→ 时间记录
  - 「选项」→ 各字典的初始选项
  - 「月日常性工作项」→ 置顶任务标记（见 5.2）
- 导入前给出预览和字段映射确认，可手动调整映射关系；导入后如果发现同一类系统存在多种写法（比如 `JAVA-招聘系统` 和 `招聘系统（JAVA）`），用 5.4 的“筛选 + 批量修改”工具整理，导入阶段不做自动纠正。
- 旧「编号」（A01/B03…）保留为只读的“旧系统编号”，作为去重和追溯依据，重复导入不会产生重复任务。

### 5.12 设置模块

字典管理已经独立成一个界面（左侧导航单独入口，见 5.4），不算在设置模块里；设置页保留的是偏“一次配置、不常打开”的项：

- 批量编辑入口（按条件筛选任务，批量修改指定字段，见 5.4）
- 标签管理（合并、重命名、删除）
- AI 服务商管理（多个 Provider 配置，分别指定用途：标题生成 / 云端向量）
- 本地向量模型管理（查看已下载模型、下载新模型、删除模型、查看占用空间）
- 搜索模式切换
- 视图默认设置（横向/纵向/看板、面板停靠左右）
- 进度看板“临近截止”天数阈值（默认 3 天，见 5.1）
- 数据导入 / 备份导出（整库导出为文件，方便你自己再备份一份，不同于 5.10 的“选中范围导出”）

## 7. 待你确认/后续可能要聊的开放问题

1. “引用量”倒序排序，你的本意是“记录条数多的任务优先”还是“最近记录更密集的任务优先”？当前设计按“关联时间记录条数”理解，如果是别的含义（比如某种业务上的引用/被依赖次数）需要单独说明字段来源。
2. 「月日常性工作项」现在设计成一个手动置顶/取消置顶的开关（5.2），不再按月份自动刷新——如果你希望它保留“按月维护”的语义（比如每月初重新勾一遍这个月要关注的常驻任务，上月的自动取消置顶），需要告诉我，我再调整成“按月份分组的置顶列表”而不是全局一份。

如果以上没问题，就按这份设计继续调整 [开发文档](./开发文档.md) 里的具体技术方案。
